# Telegram File Bot

[English](README.md) | Русский

Telegram-бот для обработки вложений `document`, `photo` и `video`: маленькие файлы скачиваются автоматически, большие попадают в общую очередь ручного скачивания.

## Запуск

1. Скопируйте `.env.example` в `.env`.
2. При необходимости измените локальные значения.
3. Запустите приложение:

```bash
npm start
```

Если задан реальный `TELEGRAM_BOT_TOKEN`, команда `npm start` запускает long polling через Telegram Bot API. Бот читает сообщения и callback updates, обрабатывает сообщения от пользователей из `AUTHORIZED_USER_IDS`, скачивает маленькие поддерживаемые файлы в `DOWNLOADS_DIR`, хранит метаданные в `SQLITE_DB_PATH` и удаляет исходные сообщения после успешной обработки, когда Telegram это позволяет.

При массовой загрузке бот обрабатывает updates последовательно и сдвигает Telegram offset только после успешной обработки update. Вызовы Telegram API ограничиваются настройкой `TELEGRAM_API_MIN_REQUEST_INTERVAL_MS`.

Для Telegram media groups обработка файлов начинается сразу для каждого update, но бот отправляет один общий итог после `MEDIA_GROUP_RESPONSE_DELAY_MS` миллисекунд без новых updates для той же группы.

Режим разработки с file watching:

```bash
npm run dev
```

## Использование бота

Пользоваться ботом могут только пользователи из `AUTHORIZED_USER_IDS`. Очередь и дедубликация общие для всех авторизованных пользователей.

Отправьте боту один из поддерживаемых типов вложений:

- `document`
- `photo`
- `video`

Неподдерживаемые вложения, например `audio`, `voice`, `sticker`, `animation`, а также обычные некомандные текстовые сообщения игнорируются. Некомандные сообщения без поддерживаемых вложений удаляются, если это возможно.

Файлы размером до `SMALL_FILE_LIMIT_BYTES` включительно скачиваются автоматически в `DOWNLOADS_DIR`. Файлы больше лимита сохраняются в общей очереди ручного скачивания.

Доступные команды:

- `/queue` — показать сводку общей очереди: количество файлов и суммарный известный размер.
- `/stats` — показать агрегированную статистику бота: общее количество файлов, известный размер файлов, размер БД, активную очередь, автоматически скачанные файлы, подтверждённые ручные скачивания, дубликаты, ошибки и типы вложений.
- `/clear_queue` — запросить подтверждение очистки общей очереди. После подтверждения активные записи очереди помечаются статусом `deleted_by_user`.

Доступные кнопки:

- `Показать следующие вложения` — начать выдачу файлов из очереди.
- `Подтвердить скачивание и показать следующие` — подтвердить скачивание предыдущей пачки и получить следующую пачку до 10 файлов.
- `Подтвердить скачивание` — подтвердить последнюю показанную пачку, когда в очереди больше нет файлов.
- `Очистить очередь` — подтвердить `/clear_queue`.
- `Отмена` — отменить очистку очереди.

Сценарий ручного скачивания:

1. Отправьте боту большие `photo`, `video` или `document` файлы.
2. Используйте `/queue`, чтобы посмотреть очередь.
3. Нажмите `Показать следующие вложения`.
4. Скачайте показанные файлы в Telegram.
5. Нажмите `Подтвердить скачивание и показать следующие`, чтобы подтвердить предыдущую пачку и получить следующую.
6. Для последней пачки нажмите `Подтвердить скачивание`.

Бот сначала выдаёт большие `photo` и `video`, затем `document`.

## Тесты

```bash
npm test
```

Тестовый набор использует только локальные Node.js модули и не выполняет сетевые запросы.

## Docker

Собрать образ:

```bash
docker build -t telegram-file-bot:stage1 .
```

Запустить контейнер:

```bash
docker run --rm telegram-file-bot:stage1
```

## Структура

- `src/application/` — оркестрация обработки сообщений.
- `src/domain/` — чистые бизнес-правила.
- `src/adapters/` — Telegram- и storage-адаптеры.
- `tests/` — unit-тесты и минимальный локальный test runner.
